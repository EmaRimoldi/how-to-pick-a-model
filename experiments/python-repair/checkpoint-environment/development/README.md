# Adapted real-bug development pool

Twelve function-level repair tasks extracted from real BugsInPy bug/fix pairs:
ten youtube-dl utilities, one HTTPie parser and one Tornado URL utility. This is
an **offline development pool**, not a new benchmark score or an evaluation holdout.
Qualification itself used no model calls. These tasks have since been used in the
[closed recovery pilot](../results/gemma4b-calibration-20261026/README.md) and
[completed contract diagnostic](../results/contract-deepinfra-20261026/README.md).
They remain development data.

All **12/12** pass offline qualification on the recorded macOS/Python 3.13.12
runtime: buggy versions fail both suites; upstream fixes pass both, twice.

The selection targets parsing/data transformations with small, standard-library
workspaces. It is purposive and dominated by one project; it is not a representative
sample of software maintenance. Every inspected bug is development-exposed.

| BugsInPy ID | Repair surface | Regression exercised |
| --- | --- | --- |
| youtube-dl/3 | HTML entities | Stray ampersand before a valid entity |
| youtube-dl/11 | Integer counts | Already numeric inputs |
| youtube-dl/13 | URL joining | Non-HTTP absolute schemes without a valid base |
| youtube-dl/20 | HTML attribute matching | Valueless attributes before/after a target |
| youtube-dl/27 | Subtitle timestamps | Colon-delimited decimal fraction |
| youtube-dl/31 | Durations | Standalone fractional minutes/hours |
| youtube-dl/32 | JSONP stripping | Trailing line comment |
| youtube-dl/33 | ISO timestamps | Fractional seconds with timezone suffix |
| youtube-dl/42 | XML ampersands | Preserving existing bounded-dialect entities |
| youtube-dl/43 | URL basename | More than two path components |
| httpie/5 | Command-line item parsing | Empty keys and escaped overlapping separators |
| tornado/9 | Query argument concatenation | `None` arguments preserve the exact URL |

## Reproduce without a model or credentials

From the repository root, with the normal development environment installed:

```bash
uv run python scripts/qualify_python_repair_pool.py
uv run python scripts/qualify_python_repair_pool.py build --output runs/real-bug-bundles
uv run python scripts/qualify_python_repair_pool.py qualify --output runs/real-bug-qualification
uv run python scripts/prepare_python_repair.py audit --input runs/real-bug-qualification/runs/httpie-005
```

The default only validates the pool. Build reads inert source excerpts; it does
not import or execute them. Qualification requires the existing macOS sandbox
backend and executes each case in a fresh isolated process. Output directories
must be new. Interrupted runs remain incomplete; no automatic overwrite/resume.
A failed engineering gate returns nonzero but preserves every task's result.

There are **71 public and 71 evaluator cases** with disjoint inputs within each
task. Each suite runs twice on both buggy and fixed code: **568 case executions**
per full qualification, plus isolation probes. Expected answers were written from
the functional contract and upstream examples, not generated by running the fix.
Both suites are published; evaluator cases are excluded from solver requests,
not claimed to be secret or independent samples of real workloads.

Qualification requires repeatable per-case outcomes, failure of the buggy version
on both suites and success of the fixed version on both. The machine-readable
[qualification report](qualification.json) records outcomes, task/runtime hashes,
per-run integrity anchors and zero API spend. The first round's Tornado adapter
failure and its correction are retained in [qualification history](qualification-history.json).
No case or upstream function was changed to resolve that adapter failure.

## Source and adaptation audit

[pool.json](pool.json) fixes the instructions, cases, compatibility imports,
wrappers, full commit IDs, source URLs, full-file SHA-256 hashes and exact extraction
line ranges. `upstream/` contains inert `.txt` excerpts of the original buggy/fixed
functions and relevant upstream tests. Function bodies remain byte-for-byte intact.
Full downloaded files remain in the ignored local source archive; they are not
needed for ordinary rebuilding/qualification.

To independently verify the extraction, retrieve each `provenance.sources` URL
from `pool.json` into `<cache>/<benchmark_id>/<role>.txt`, then run:

```bash
uv run python scripts/qualify_python_repair_pool.py audit-sources --source-cache runs/python-repair-real-bug-sources-20261025
```

This performs no network calls: it checks the full-file hashes and every extracted
line range against downloaded originals. The delivered [source audit](source-audit.json)
records the verified source count and pool hash. BugsInPy metadata is pinned at
[`11c5f1ee`](https://github.com/soarsmu/BugsInPy/tree/11c5f1eea954a42132cfd06bf257766a7963e0fd).
Project licenses and attribution are retained in `licenses/`; they apply to the
upstream excerpts independently of this repository's own license.

Adaptations are intentionally explicit:

- Unrelated modules/imports are removed; Python 3 compatibility names map to their
  standard-library counterparts. The host uses a modern Python runtime, not the
  original Python 3.7/3.8 project environment.
- The HTTPie wrapper exposes the namedtuple as a JSON object and maps
  `argparse.ArgumentTypeError` to `ValueError`. It never accesses a file or network.
- The Tornado wrapper converts JSON key/value arrays to Python tuples, identically
  for buggy and fixed versions. The first attempted adapter lacked that conversion.
- youtube-dl/42 retains the upstream function rename through different wrapper
  bindings. Its historical entity-length restriction is part of the stated scope.
- For youtube-dl/31, /32, /33 and /42, only the utility component of a multi-file
  upstream fix is represented. Extractor and integration behavior is not evaluated.

[screening.json](screening.json) retains the 169 patch-header records inspected
across six projects and detailed exclusions (including earlier Cookiecutter
inspection). Not selected does not mean tested and failed. Dependency-heavy,
filesystem-specific, platform-dependent and overlapping function variants were
left out; the original patches are not silently rewritten to fit the harness.

## What this establishes

The fixtures can expose their historical defects and recognize the supplied
upstream fixes under this adapter and runtime. They do **not** establish exhaustive
correctness, absence of pretraining contamination, natural intermediate progress,
model difficulty or a benefit of continuing over restarting. Many fixes are tiny
and could be too easy for the intended recovery experiment.

The Gemma 3 4B recovery pilot and separate contract diagnostics are now recorded.
No format passed the latest calibration gate. A new capability/calibration study
is required before fitting a selector; inspect the linked results before any
further collection. If it does not, retain that negative calibration rather than manufacture
partial LLM attempts. Keep all variants of these functions and inspected bug IDs
out of any future fresh-task evaluation. Historical budgets are closed.
