# Broaden the experimental population before another small model screen

Six components still cover only Black and tqdm, with shared functions among
three tqdm versions. Adding draws cannot create new independent bug families.
The existing package milestone removes one engineering restriction, but does not
make this population adequate for the goal. The original BugsInPy qualification
and all 34 source decisions remain retained; no hard case is silently replaced.

does not prove the archive is currently accessible or complete.

does not resolve in this environment; the current full-archive link returns
HTTP 200 with gzip MIME type to HEAD. FixEval's Python/test links return HTTP

No archive body was requested. These observations require resolving the actual
data route before choosing this source, not silently omitting missing tests.
The software repositories declare MIT and Apache-2.0 respectively; the rights
for the separately hosted data/test artifacts still need verification.

The FixEval paper's public illustrative **biscuit-machine problem** and its
Java bug/fix were visible during this literature inspection. If this source is
used, that problem and equivalent variants must be excluded from any untouched
evaluation claim. The CodeNet README also exposes illustrative metadata for
problem `p00001`; conservatively exclude that family from untouched claims if
this source is adopted. No claim of zero global exposure is made. No dataset source,
fix or test archive was downloaded in this source review.

## Next operational boundary

Before viewing any additional bug contents, extend the recorded metadata-only
plan to resolve public download landing pages and artifact licensing, without
requesting candidate source or test bodies. Use it to decide whether a broad
population can be qualified with independent problem families and genuinely
separate tests. Then freeze the source selection/split before opening items.
The seven remaining BugsInPy project groups remain unopened in the meantime.

If a competitive-programming population is feasible, it would be an explicitly
separate domain for the diagnostic mechanism, retaining a repository-repair
validation requirement for the product claim. If it is not feasible, record the
failure and continue qualifying original package contexts. Do not accept
AST validity, exact patch matching, synthetic dependency behavior or a few
repeated easy examples as substitutes for functional repair.

The next model protocol must collect genuine failed repair checkpoints before
F/N/S assignment, retain failures/missingness, select the numerical sample and
primary analysis prospectively, and reserve all calls under an authorized cap.
Only replicated diagnostic value can justify the later selector experiment.
