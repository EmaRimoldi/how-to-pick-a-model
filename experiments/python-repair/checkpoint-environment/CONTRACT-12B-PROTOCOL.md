## Gate and interpretation

Use the unchanged complete-bank gate: at least three distinct fully solved bugs,
ten syntax-valid artifacts with the declared entrypoint and two such artifacts
still unsolved. If multiple contracts qualify, select more solved bugs, then
lower actual API charges, then declared contract order. An incomplete bank is
inconclusive. Report actual full-pass counts for all contracts even if none
qualifies. This is an operational calibration threshold, never an emergence test.

One draw per already inspected bug/contract cannot support a held-out conclusion,
a scaling exponent, a discontinuity or robust action complementarity. This bank
has initial repairs only; it does not measure continue/restart recovery or fit a
selector. A candidate format would require a separately frozen recovery study.
Do not pool the new and earlier banks. Both pretraining data and model size vary
within Gemma 3, and provider sampling/order also differ here. A future size-curve
experiment needs repeated draws, common checkpoints and distinct natural-failure
analysis, as explained in the [literature review](../../../docs/recovery-related-work.md).
