# Additional development bugs: Luigi and The Fuck

Three previously inspected BugsInPy IDs add two projects to the repair development
material. They are separate from the original twelve-task pool. Initial
qualification was offline; the subsequent [independent trace calibration](../results/information-extension-stopped-20261026/README.md)
received 9/24 responses before its transport stop and remains inconclusive.
They are not a holdout, an official BugsInPy score, or evidence that execution
traces improve repair.

| Bug | Declared function-level scope | Adaptation boundary |
| --- | --- | --- |
| luigi/3 | Parse numeric tuple/list literals into tuples | Full upstream parser classes; inert base-class stub; JSON wrapper exposes the outer type. No scheduler, normalization or mapping inputs. |
| thefuck/10 | Construct ordered manual-page suggestions from a command and stderr | Inert command container and POSIX tokenization. No shell detection or execution. |
| thefuck/20 | Construct a correctly quoted unzip destination | Original string-transform functions and POSIX quoting. No archives, filesystem, side effects or shell execution. |

All three pass [qualification](qualification.json): each initial version fails
both suites, and each original fixed version passes both, twice. Six public and
six evaluator cases per task have distinct inputs. That is 144 ordinary case
executions, plus sandbox probes. These hand-authored expectations follow the
declared restricted contracts and upstream examples; they were not generated by
executing a reference solution. Both suites are published development data.
The incomplete calibration does not establish useful diagnostic headroom.

The [screening record](screening.json) retains all six inspected candidates,
including the three deferred because they would omit material state/dependency
behavior or overlap a parser family. This purposive selection precedes model
results but does not make the tasks representative of software maintenance.

## Reproduction and provenance

[pool.json](pool.json) uses the existing builder. Original buggy/fixed function
and class excerpts are preserved byte-for-byte as inert text, alongside relevant
upstream tests and licenses. Wrapper/import adaptations are explicit. Packaging
preserved the previously qualified source artifacts, instructions and test cases.
[source-audit.json](source-audit.json) verifies 17 full-file hashes and the extracted
ranges against pinned downloads, including support code used to justify adapters.
The exact source URLs and commits are in the pool; no upstream setup is executed.

From the repository root:

```bash
uv run python scripts/qualify_python_repair_pool.py --pool experiments/python-repair/checkpoint-environment/development-extension
uv run python scripts/qualify_python_repair_pool.py build --pool experiments/python-repair/checkpoint-environment/development-extension --output runs/extension-bundles
uv run python scripts/qualify_python_repair_pool.py qualify --pool experiments/python-repair/checkpoint-environment/development-extension --output runs/extension-qualification
```

Qualification requires the documented macOS sandbox backend and fresh output
directories. For independent extraction checking, download each pool source URL
as `<cache>/<benchmark_id>/<role>.txt`, then run the existing `audit-sources`
action with `--pool` as above and `--source-cache <cache>`. Ordinary builds and
qualification use only published files and need no network or model credentials.

All IDs and variants remain development-exposed in the consolidated
[exposure registry](../development/exposure-registry.json). Absence from that
registry cannot certify that another case is untouched. Before model collection,
freeze a distinct protocol, exact prompts, cost limits and missing-data rules;
do not repurpose this extension as a continuation of the interrupted Qwen bank.
