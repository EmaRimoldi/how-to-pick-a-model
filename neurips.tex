\begin{abstract}
This is a structural skeleton, not a polished rewrite.
The unified paper studies how to choose among model and agent-system designs for verifiable tasks.
Under a packed latent-mode assumption, the performance gap between two designs decomposes into cost, competence, routing information, and routing mismatch.
The paper will use this decomposition to derive practical model-selection diagnostics, a decomposition-guided selection algorithm, crossover rules for cheap models with retries, and transfer rules for reusing designs across task families.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

\paragraph{Planned role.}
Open with the builder's problem: a practitioner has a task family, a budget, a menu of models, possible retry depths, and possible routing policies.
The naive method is benchmark racing: evaluate every candidate design end-to-end and pick the best.
Benchmark racing is simple but opaque: it conflates per-step cost, per-mode competence, information available for routing, and routing mismatch.

\paragraph{Central thesis.}
The paper should argue that model choice in agentic systems is a structured measurement problem.
Under a packed latent-mode abstraction for verifiable tasks, the performance gap between designs admits a four-term accounting identity.
This identity does not directly solve the optimization problem, but it tells the builder which lever matters and enables sample-efficient ranking of large design menus from a shared pilot.

\paragraph{Contributions to write.}
\begin{enumerate}[leftmargin=1.4em]
  \item A packed latent-mode setup for verifiable agent design.
  \item An exact four-term decomposition into cost, competence, information gain, and routing mismatch.
  \item A crossover rule explaining when a cheaper model with retries beats a more expensive model.
  \item A decomposition-guided design-selection algorithm with evaluation cost independent of the number of candidate designs once pilot estimates are collected.
  \item Experiments validating ranking, robustness, and sensitivity of the resulting design choices.
  \item A transfer/reuse framework distinguishing competence transfer from orchestration transfer.
\end{enumerate}

\section{Decomposition-Guided Design Selection}
\label{sec:algorithm}

\subsection{Algorithm}
\label{sec:algorithm-box}

\paragraph{Planned algorithm.}
\begin{enumerate}[leftmargin=1.4em]
  \item Structured pilot: estimate $\hat p(s,M)$ for each model-mode pair.
  \item Analytical scoring: compute the decomposition objective for every candidate design without end-to-end racing.
  \item Confirmation: evaluate only the top candidates on fresh instances.
\end{enumerate}

\paragraph{Main point.}
Once the model-mode success table is estimated, scoring is arithmetic.
The number of task evaluations scales with number of models and modes, not directly with the number of candidate designs $k$.

\section{Discussion, Limitations, and Future Directions}
\label{sec:discussion}

\paragraph{What the paper should leave readers with.}
The decomposition is valuable because it turns "which model should I pick?" into separately measurable questions.
It is an accounting identity and diagnostic tool, not a universal optimizer.

\paragraph{When not to use the framework.}
Single-mode tasks, no pilot data, rapidly shifting distributions, tiny design menus, and cost-adjusted homogeneous model menus where routing is trivial.

\paragraph{Open questions.}
\begin{itemize}[leftmargin=1.4em]
  \item How should latent modes be discovered rather than supplied by oracle workload families?
  \item How does the decomposition degrade under non-geometric certified-time distributions?
  \item How should practitioners choose among expectation, quantile, and cost-adjusted ranking metrics?
  \item Can the pilot/confirmation budget split be optimized theoretically?
  \item When does transfer reuse work in real agent deployments?
  \item How does the framework extend to continuous design spaces and dependent multi-step agents?
\end{itemize}
